IaC security best practices

Shift-left IaC security — scan before deploy
Run Checkov as a pre-commit hook with the pre-commit framework: add checkov -d . to run on every commit. Add it to GitHub Actions to block PRs with HIGH severity misconfigurations. The goal is catching issues at commit time — not in production audit reports. Command: checkov -d ./infrastructure --check CKV_AWS_* --soft-fail-on MEDIUM. This runs all AWS checks and fails hard on HIGH/CRITICAL, soft-fails on MEDIUM.

The most dangerous IaC misconfiguration: IAM Action:* Resource:*
An IAM policy with "Action": "*" and "Resource": "*" grants god-mode access to the entire AWS account. This is the most common finding in cloud security breaches. Principle of least privilege: list only the specific actions and resources each role needs. Use AWS-managed policies as a starting point, then scope down. For EC2 instance roles, limit to the specific S3 bucket and DynamoDB table the application uses — not all S3 and all DynamoDB.

Security group 0.0.0.0/0 on SSH (port 22) and RDP (port 3389)
Opening SSH or RDP to the entire internet exposes your instance to brute force attacks and zero-days. Instead: use AWS Systems Manager Session Manager for shell access (no port 22 needed), or restrict to specific CIDR blocks (your office IP, VPN IP). For databases: never expose port 3306 (MySQL), 5432 (PostgreSQL), 6379 (Redis) to the internet — databases should only accept connections from application security groups within the same VPC.

FAQ — IaC security tools
Free: Checkov (broadest IaC support, 1000+ policies, CI/CD ready), tfsec (Terraform-only, fastest), Trivy (multi-purpose including IaC), KICS (2000+ queries). Freemium: Snyk IaC (great CI/CD integration, fix suggestions). Enterprise: Prisma Cloud, Orca Security (agentless). For most teams: Checkov in CI/CD as a GitHub Action, plus tfsec as a pre-commit hook gives excellent coverage at zero cost. Run: checkov -d . --framework terraform.
IaC security scanners check for misconfigurations in infrastructure code before deployment: open security groups (SSH/RDP to 0.0.0.0/0), overly permissive IAM policies (Action:*, Resource:*), public S3 buckets, unencrypted storage (EBS, RDS, S3), hardcoded credentials, missing logging (CloudTrail, VPC Flow Logs), publicly accessible databases, missing MFA delete on S3, unencrypted data in transit (HTTP endpoints), and hundreds of cloud provider-specific checks against CIS Benchmarks and compliance frameworks (SOC2, PCI-DSS, HIPAA).
GitHub Actions with Checkov: add a step uses: bridgecrewio/checkov-action@master with directory: .. This runs on every PR and fails if HIGH severity issues are found. For tfsec: uses: aquasecurity/tfsec-action@v1.0.0. For Trivy IaC: trivy config --exit-code 1 --severity HIGH,CRITICAL ./. Best practice: run fast scanners (tfsec) as pre-commit hooks and comprehensive scanners (Checkov) in CI/CD to balance speed with coverage.
